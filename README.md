# SAINTEL

**S**outh **A**sian **I**nfrastructure — **N**ative **T**hreat **E**ntity **L**abelling.
A research pipeline that extracts critical-infrastructure entities from
code-switched South Asian text without translating it to English first, and a
deliberate near-homophone of *sentinel*: a watchman set over infrastructure.

Scope note: the four commitments in the name are validated to different
degrees. *Native* and *entity labelling* are measured here (F1 0.866, and 0.875
on held-out infrastructure entities). Coverage beyond Tamil is future work.

> **Status: research prototype.** This is an active research codebase, not a
> deployed system. All evaluation data is **synthetic and authored for
> defensive research**. See [Limitations](#limitations) before citing any
> number here.

## What this is, and what it is not

SAINTEL ingests OSINT text (Telegram, ransomware leak sites, threat feeds),
extracts entities in **native script** — Tamil, and by extension other Indic
scripts — and builds a Neo4j threat graph with STIX 2.1 export.

The `tests/data/` evaluation set contains **synthetic** sentences describing
hypothetical attacks on Indian critical infrastructure. They were written to
measure a *defensive* detection system, are labelled `"source": "synthetic"`,
and describe no real event, plan, or capability. Adversarial evaluation data is
standard practice in security research; it is included so results are
reproducible and falsifiable.

## The problem it addresses

Multilingual NER tokenizers fragment mixed-script entities. `DRDO` inside Tamil
prose becomes `dr` + `##do`; `சென்னை` loses its virama and decodes as `செனனை`.
Off-the-shelf `ai4bharat/IndicNER` scores **F1 0.186** on this task, and is
*confidently* wrong — it tagged the two-character fragment `dr` as an
organization at 0.911 confidence.

## Results

Measured on the held-out `test` split (37 records), value-level scoring.
`held_out` = CNI entities deliberately absent from the gazetteer, so a lookup
table scores 0 there by construction — that column is the generalisation test.

| Arm | P | R | F1 | held_out F1 | native_tamil F1 |
|---|---|---|---|---|---|
| gazetteer only | 1.000 | 0.667 | 0.800 | 0.000 | 1.000 |
| IndicNER (base) | 0.151 | 0.242 | 0.186 | 0.210 | 0.000 |
| fine-tuned | 0.758 | 0.758 | 0.758 | 0.875 | 0.333 |
| **fine-tuned + gazetteer** | 0.853 | 0.879 | **0.866** | **0.875** | **0.923** |

The two components are complementary: the fine-tuned model generalises to
entities it never saw (0.875 where the gazetteer is structurally 0.000), while
the gazetteer carries native Tamil (1.000) where the model collapses (0.333).

Decisions and their evidence: [ADR-001](docs/adr-001-rules-vs-finetuning.md)
(superseded) → [ADR-002](docs/adr-002-finetuned-hybrid.md).

## Quickstart

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # then fill in real values
pytest tests/ -q              # 73 assertions, no infrastructure needed
```

Reproduce the results end to end:

```bash
python scripts/build_eval_seed.py         # evaluation set
python scripts/build_finetune_corpus.py   # training corpus (leakage-checked)
python scripts/finetune_indicner.py       # ~10 min on Apple MPS
python scripts/evaluate_pipeline.py --split test --arms all
```

Everything is deterministically seeded. The fine-tuned model (~640 MB) is
gitignored and regenerated by the script above.

Build a real corpus (the blocking item for publication):

```bash
python src/layer1_ingestion/capture_sink.py        # archive raw traffic, resumable
python scripts/sample_for_annotation.py --n 300    # stratified, PII-redacted worksheet
# label per tests/data/annotation_guidelines.md, second annotator on 20% for kappa
```

Run the pipeline (needs Kafka + Neo4j via `docker compose up -d`):

```bash
python src/layer3_native_nlp/entity_extractor.py   # extract -> layer3_entities
python src/layer4_graphrag/neo4j_connector.py      # persist to Neo4j
streamlit run src/ui_dashboard/app.py              # analyst console
```

## Architecture

```
Layer 0/1  scrapers (Telegram, Tor leak sites, RansomLook) ──> Kafka raw topic
           Tor path needs a local Tor daemon: SOCKS 9050 + control 9051
                                                            └──> capture sink -> data/raw/*.jsonl
Layer 2    fastText triage                       [NOT in the data path -- see below]
Layer 3    NFKC normalise -> fine-tuned IndicNER -> gazetteer repair
Layer 4    Neo4j threat graph
Layer 5    STIX 2.1 export  +  Streamlit console
```

## Limitations

Read these before treating any number above as meaningful.

1. **Training and evaluation data share authorship and sentence templates.**
   Generalisation is demonstrated over *entity identity*, not over *linguistic
   register*. Real hacktivist text — slang, misspellings, irregular syntax — is
   not represented. **0.866 is an upper bound, not a field estimate.**
2. **Tamil is unverified.** Records carry `tamil_verified: false` pending review
   by a fluent reader.
3. **The overall advantage is not statistically significant.** gazetteer vs
   fine-tuned+gazetteer: McNemar b=3, c=5, p>0.05 at n=37. The *held_out*
   difference is categorical and needs no test; the overall margin does not
   survive one.
4. **The triage classifier is unusable.** Trained on 14 hand-written examples,
   it measures recall 0.250. It is deliberately **not** wired into the data
   path — routing Layer 3 behind it would discard ~75% of real threats.
5. **The intent classifier is invalid for this task.** `bart-large-mnli` is
   English-only; on Tamil its label distribution flattens toward uniform. It is
   guessing.
6. **`tactic` entities are unlearnable** with IndicNER's LOC/ORG/PER head.
7. Entity scoring is value-level, not span-level — the pipeline discards
   character offsets. Gold data stores them and will upgrade for free.
8. **No real harvested corpus exists yet.** A capture sink now archives raw
   traffic (`src/layer1_ingestion/capture_sink.py`), but it has not yet been
   run against live sources, so every number above still rests on synthetic
   data. This is the single blocking item for publication.

## Ethics and data handling

Ransomware leak-site scraping touches victim PII. Record the claiming group and
the fact of a claim; **never store individual names, addresses, or documents**.
Any harvested corpus needs a documented collection protocol. A system that
profiles regional-language communications carries real potential for harm — a
false positive is not a wasted CPU cycle, it is a person wrongly flagged.
